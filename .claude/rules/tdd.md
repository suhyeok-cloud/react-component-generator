# TDD Rule

> **이 규칙은 Rigid — 상황에 맞게 변형하지 마라.**
> 단계를 건너뛰거나, 순서를 바꾸거나, 일부만 적용하지 않는다.

## 우선순위

- 프로젝트의 `CLAUDE.md` / `AGENTS.md`에 TDD 규칙이 있으면 **그 규칙이 우선**한다.
- 이 파일은 프로젝트 규칙이 없을 때 쓰는 **기본값(fallback)** 이다.
- 두 규칙이 충돌하면 프로젝트 규칙을 따르고, 충돌하지 않는 부분은 이 파일을 따른다.

## 1. 적용 기준

### TDD를 반드시 적용

- 비즈니스 로직
- API (엔드포인트, 요청/응답 처리, 에러 분류)
- 유틸리티 / 순수 함수
- **버그 수정** (재현하는 실패 테스트를 먼저 작성한 뒤 고친다)

### TDD 불필요

- 타입 정의 (`type`, `interface`)
- 설정 파일
- 순수 UI (스타일, 레이아웃, 마크업만 바꾸는 변경)
- SQL (스키마, 마이그레이션)

판단이 애매하면 **적용 대상으로 간주**한다. 동작(분기, 계산, 상태 변화)이 하나라도 있으면 테스트 대상이다.

## 2. RED - GREEN - REFACTOR

### RED: 실패하는 테스트 작성

- **하나의 동작 = 하나의 테스트.** 한 테스트에 여러 동작을 담지 않는다.
- 테스트 이름은 동작을 설명한다 (예: "빈 입력이면 에러를 던진다").
- **반드시 실행해서 실패를 눈으로 확인한다.** 실행하지 않은 테스트는 RED가 아니다.
- 실패 이유가 **"기능 미구현"** 이어야 한다. 문법 오류, import 오류, 오타, 잘못된 셋업으로 인한 실패는 RED가 아니므로 테스트를 고친 뒤 다시 실행한다.
- 처음부터 통과하는 테스트는 아무것도 증명하지 못한다. 테스트나 대상 동작을 다시 점검한다.

### GREEN: 최소한의 코드로 통과

- 테스트를 통과시키는 **최소한의 코드만** 작성한다.
- **YAGNI**: 지금 테스트가 요구하지 않는 옵션, 분기, 확장 포인트는 만들지 않는다.
- **신규 테스트와 기존 테스트 모두** 실행해 전부 통과하는지 확인한다.
- 실패하는 테스트가 남아 있으면 GREEN이 아니다. REFACTOR로 넘어가지 않는다.

### REFACTOR: 정리

- 중복 제거, 이름 개선, 헬퍼 추출만 한다.
- **모든 테스트가 green인 상태를 유지한다.** 수정할 때마다 테스트를 실행한다.
- **새 동작을 추가하지 않는다.** 새 동작이 필요하면 다음 RED에서 시작한다.

### 반복

REFACTOR가 끝나면 **다음 동작에 대한 RED로 돌아간다.** 요구된 동작이 모두 테스트로 덮일 때까지 반복한다.

## 3. 삭제 강제 규칙

테스트보다 프로덕션 코드를 먼저 작성했다면:

1. 그 프로덕션 코드를 **삭제한다.**
2. **RED부터 다시 시작한다.**
3. "참고용"으로 남기거나, 주석 처리하거나, 다른 곳에 복사해 두는 것도 **금지**한다. 보고 베끼면 테스트가 코드에 맞춰진다.

## 4. 변명 차단표

| 변명 | 반론 |
| --- | --- |
| 너무 단순해서 테스트가 불필요하다 | 단순한 코드는 테스트도 30초면 끝난다. 단순한 코드에서도 버그는 나오고, 나중에 복잡해질 때 이 테스트가 안전망이 된다. |
| 나중에 테스트를 추가하겠다 | 나중에 쓴 테스트는 구현을 따라가며 통과하도록 쓰게 된다. "나중에"는 오지 않는다. |
| 시간이 없다 | 디버깅과 회귀 수정에 드는 시간이 테스트 작성 시간보다 길다. 급할수록 TDD가 더 빠르다. |
| 삭제하면 낭비다 | 이미 쓴 코드는 매몰 비용이다. 검증되지 않은 코드를 유지하는 것이 더 큰 비용이다. 다시 쓰는 건 이미 아는 내용이라 빠르다. |
| 프로토타입이다 | 프로토타입은 그대로 제품이 되는 일이 많다. 버릴 코드라면 애초에 TDD 대상이 아니라고 사용자가 명시해야 한다. 내가 임의로 판단하지 않는다. |

## 완료 전 확인

- [ ] 모든 새 동작에 먼저 실패한 테스트가 있다
- [ ] 각 RED의 실패 이유가 "기능 미구현"이었다
- [ ] 각 GREEN은 최소 코드였다
- [ ] 신규 + 기존 테스트가 전부 통과한다
- [ ] 테스트 전에 쓴 프로덕션 코드는 남아 있지 않다

하나라도 체크할 수 없으면 완료가 아니다.
